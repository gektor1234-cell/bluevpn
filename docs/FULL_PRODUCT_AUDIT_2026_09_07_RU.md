## Итог

**Приложение нельзя считать полностью проверенным и законченным.** Публичные загрузки, серверы и значительная часть автоматических проверок работают. ## Найденные проблемы

### A01. P1 — Очистка истёкшей подписки удаляет доступ после продления

**Статус: REPRO.** `reconcile_expired_subscriptions` выбирает кандидатов, затем перечитывает запись внутри транзакции. Если подписку уже продлили, изменение БД пропускается. Но последующий цикл удаления peers использует исходных кандидатов, а не только действительно истёкшие и не изменившиеся подписки.

Локальная фикстура продлила подписку между двумя чтениями БД. Результат: `changedCount=0`, подписка активна с будущим сроком, вызов удаления peers всё равно произошёл один раз. Реальное удаление заменено mock-функцией. Инцидент на production этой проверкой не устанавливается.

Источник: [reconcile_expired_subscriptions](/C:/Users/gekto/projects/bluevpn/backend_live/app/main.py:20567), [remove_user_subscription_peers](/C:/Users/gekto/projects/bluevpn/backend_live/app/main.py:20249). Evidence: `backend-isolated-probes.jsonl`, `expiry-race.json`.

**Исправление:** связать отложенный отзыв с ревизией/поколением entitlement и согласовать его с продлением. Одного удаления пользователя из первоначального списка недостаточно: нужна защита от продления уже между транзакцией и внешней SSH-операцией. **Закрытие:** конкурентные продление, ручная выдача, webhook и expiry не удаляют действующие peers; действительно истёкший доступ отзывается на всех поддерживаемых узлах.

### A02. P1 — Android после паузы теряет выбранный режим

**Статус: CODE.** Пауза разрешена без ограничения `socialOnly`. Flutter передаёт в `scheduleRuntimeResume` время, сервер и протокол, но не список и режим. Native `scheduleResume` записывает `KEY_REQUESTED_MODE="full"`, а `fetchFreshConfig` запрашивает `mode=full`. Обычный WireGuard config затем запускается напрямую.

Следствие: сценарий «только выбранные → пауза → автоматический возврат» не сохраняет обещанную маршрутизацию. В этом аудите телефон не переключался; это доказанная потеря параметров в коде, а не запись живого трафика.

Источники: [передача параметров паузы](/C:/Users/gekto/projects/bluevpn/lib/main.dart:8276), [native scheduleResume](/C:/Users/gekto/projects/bluevpn/android/app/src/main/kotlin/pro/greenvpn/app/GreenVpnRuntimeFailoverService.kt:241), [запрос full](/C:/Users/gekto/projects/bluevpn/android/app/src/main/kotlin/pro/greenvpn/app/GreenVpnNativeCascadeCoordinator.kt:375).

**Исправление:** сохранять режим, список приложений и operation epoch как одну операцию; не подменять неподдерживаемый режим полным. **Закрытие:** после паузы выбранное приложение идёт через VPN, невыбранное — напрямую, UI совпадает с native runtime, в том числе при закрытом Flutter UI.

### A03. P1 — Защита выбранного сайта не покрывает домен целиком

**Статус: CODE / CONDITIONAL.** Windows резолвит apex/`www` только в IPv4 и строит снимок `/32`. Отдельного полного domain-aware маршрутизатора здесь нет. В site-only режиме process-router не обязателен. При невыбранном браузере IPv6 назначения, новые адреса CDN и дополнительные поддомены не покрываются таким правилом. Общий IPv4, наоборот, может захватить другой сервис.

Это не обвинение в утечке выбранного executable: у него отдельная схема перехвата. Условие проблемы — именно защита сайта без выбора всего процесса браузера. Свежий физический IPv6-тест не выполнялся.

Источники: [IPv4 resolution](/C:/Users/gekto/projects/bluevpn/lib/services/windows_selective_routing_service.dart:148), [применение маршрутов](/C:/Users/gekto/projects/bluevpn/lib/main.dart:10407), [site-only без обязательного router](/C:/Users/gekto/projects/bluevpn/scripts/windows/greenvpn_vpn_task.ps1:1127).

**Исправление:** определить честный контракт сайтов и реализовать его с DNS/TTL/CDN/IPv6 либо явно ограничить доступность неподдерживаемых сценариев. Не добавлять небезопасную атрибуцию по одному remote IP. **Закрытие:** A/AAAA, смена DNS-адреса, subdomain/CDN, DoH и общий IP проверены отдельно, выбранный трафик не выходит напрямую.

### A04. P1 — Обязательное обновление может зависнуть без выхода

**Статус: CODE / CONDITIONAL.** Загрузка использует `HttpClient`, но не задаёт прикладные deadlines для получения ответа, ожидания следующего блока и всей операции; нет отмены и ограничения размера. Сервер может принять запрос или прислать часть файла и не завершить поток. При обязательном обновлении пользователь остаётся на заблокированном экране со статусом загрузки.

Источники: [download](/C:/Users/gekto/projects/bluevpn/lib/main.dart:21812), [обязательный экран и действия](/C:/Users/gekto/projects/bluevpn/lib/main.dart:21890). Новая загрузка действительно скачивается сейчас; дефект относится к негативному сетевому сценарию.

**Исправление:** ограниченные connect/header/idle/total сроки, потоковая проверка размера/хэша, отмена, повтор и очистка partial-файла. Отмена загрузки не должна снимать обязательность обновления. **Закрытие:** локальные серверы с зависшими headers/body, обрывом и oversized response всегда переводят UI в конечное понятное состояние без запуска неполного файла.

### A05. P1 — Клиент обновления допускает неполный manifest

**Статус: REPRO + CODE; риск условный.** `canDownload` принимает непустой URL без обязательных `sha256`/размера/`fileReady`. Если digest пуст, проверка ранее загруженного файла принимает любой непустой файл. Отдельная фикстура подтвердила: при отсутствии `updateAvailable` manifest с более старой версией рассматривается как обновление, поскольку сравниваются строки на неравенство.

Текущие публичные manifests содержат корректный digest, и четыре файла совпали. Подмена текущего релиза не установлена. Отсутствие Authenticode усиливает последствия обхода проверки метаданных, но само по себе не доказывает атаку.

Источники: [manifest model](/C:/Users/gekto/projects/bluevpn/lib/main.dart:3049), [пустой digest](/C:/Users/gekto/projects/bluevpn/lib/main.dart:21698), [запуск файла](/C:/Users/gekto/projects/bluevpn/lib/main.dart:21882). Evidence: первые два случая в `audit-ui-probes.log`.

**Исправление:** строгая схема manifest: 64 hex SHA, положительный ограниченный размер, готовность файла, монотонное сравнение версии, политика допустимого финального HTTPS-адреса. Повторно проверять точные байты перед запуском, включая cache. **Закрытие:** отсутствующие/неверные поля, downgrade, изменённый cache и обрыв загрузки запрещают установку; нормальный manifest работает.

### A06. P1 — Распаковка отчёта поддержки не ограничена

**Статус: REPRO.** Ограничение 250 000 символов наложено на сжатую строку. Далее `gzip.decompress` распаковывает весь документ в память до JSON parsing и очистки. Декодирование вызывается уже при определении категории поступившего отчёта, а не только при открытии администратором.

Безопасная локальная фикстура: 10 942 байта закодированного отчёта приняты и распакованы в 8 388 628 байт. Это намеренно ограниченная демонстрация; большие payload и production endpoint не использовались. Возможен расход памяти и CPU при злоупотреблении авторизованным endpoint, в том числе через гостевой аккаунт.

Источники: [ограничение входа](/C:/Users/gekto/projects/bluevpn/backend_live/app/main.py:8347), [распаковка](/C:/Users/gekto/projects/bluevpn/backend_live/app/main.py:8472), [приём](/C:/Users/gekto/projects/bluevpn/backend_live/app/main.py:37294). Evidence: `backend-isolated-probes.jsonl`.

**Исправление:** потоковая распаковка с жёстким лимитом decoded bytes, предельные глубина/число полей/строки, rate-limit и ограничение ресурсов обработки. **Закрытие:** превышение лимита отвергается до полной распаковки и хранения, нормальные отчёты остаются совместимыми.

### A07. P1 — Малый резерв диска и неполная retention-политика

**Статус: LIVE + CODE.** На fallback при проверке свободно `626659328` байт, примерно 597,6 MiB. Сейчас SQLite и службы исправны; нехватка диска или повреждение БД не произошли в наблюдаемом снимке. Но запас мал для следующих бэкапов, staging и журналов.

## Дополнительные риски и открытые условия

- **Windows доверие к установщику.** Exact installer остаётся NotSigned по release evidence. Понятная надпись на сайте не заменяет подпись, репутацию и проверку установки на чистом ПК. Это известное отложенное ограничение, не новая подписка/платёжная задача.
- **Статические альтернативные transport-конфиги.** В backend есть ветки загрузки общего статического конфига; peer cleanup специализирован под WG/AWG. Перед публичным включением таких маршрутов надо доказать индивидуальный отзыв доступа. Текущие активные публичные записи в прочитанной таблице каталога — три `remote_ssh_wg0` / `wireguard_udp`. Поэтому обход платного доступа на реально включённом static-route этим аудитом не заявляется.
- **Административная сессия.** `saveSession(remember)` в `admin_support_app/app.js:3640` сохраняет admin/session credential в `localStorage`. XSS не найден и не эксплуатировался; существуют экранирование/CSP и server-side staff checks. Тем не менее persistent owner credential требует отдельного hardening и модели угроз общего компьютера.
- **Чеки и автосписания.** Production режим сейчас manual NPD, автосписания выключены. Прохождение API checks не означает готовность автоматической выдачи чека или автопродления. В обезличенных данных видны активированный, отменённые и возвращённый заказы; это не новый контрольный платёж и не юридическое подтверждение полноты чеков. Реальные операции не создавались.
- **Первоначальная жалоба на окно загрузки.** Последний Windows patch исправляет окно завершения установщика. У сайта прямые download-ссылки, своего JS-окна «Готово» нет. Native окно браузера, его выбор папки и installer completion — разные этапы; нельзя объявлять все три исправленными одной правкой installer. Для полного UX acceptance их нужно пройти отдельно.
- **Монолит и дублирование состояний.** Большие `main.dart`/`main.py`, параллельные Dart/native state machines и normal/preview Windows tasks повышают риск расхождения. Это не повод переписывать всё заново: сначала нужны контракты и воспроизведения A01–A17, затем узкое выделение владельцев состояния.

### Обязательная физическая матрица после исправлений

1. **Сайт → файл → installer.** Новый browser session, обе ОС, понятный download/Save As, отказ от загрузки, нехватка диска, exact hash, Windows UAC/SmartScreen, отмена установщика и успешное завершение без лишнего «Готово».
2. **Upgrade / rollback / uninstall.** Чистая установка и обновление поверх поддерживаемых предыдущих версий, неадминистратор, сохранение аккаунта/списков, занятые файлы/служба, прерванная установка, возврат и удаление без оставшихся собственных маршрутов.
3. **Первый запуск.** Новая guest-сессия, free/paid, отсутствие сети, недоступность primary, fallback, валидный и невалидный токен; отсутствие ложной «защиты» до подтверждения runtime.
4. **Email.** Настоящая доставка одного кода, поздняя доставка, resend, неверный/истёкший код, другой email, два устройства, перенос подписки без потери активного периода.
5. **Владелец VPN.** Чужой VPN → явный Green takeover; Green → явный чужой VPN; сеть пропадает/возвращается; Green не возвращается сам после revoke. Проверять operation IDs и фактический владелец, а не один label.
6. **Фоновый Android.** Сворачивание на каждом этапе подключения, блокировка экрана, уничтожение UI-процесса, Doze, reboot/force-stop по определённому контракту; повторное открытие не создаёт новую конкурирующую операцию.
7. **Нестабильная сеть.** Wi-Fi↔LTE, полностью offline, validation blocked, captive portal, packet loss и длительные задержки. Потеря сети не означает пользовательский disconnect; retry ограничен и не конфликтует с новым намерением.
8. **Режимы.** Full→редактор выбранного→Cancel сохраняет действующий full; Done применяет ровно один переход. Selected executable/site и невыбранный control имеют нужный egress. Проверить IPv4/IPv6/DNS/QUIC/CDN, child processes и обновлённый Appx path.
9. **Пауза.** Full и selected, app foreground/background, изменение времени, другой VPN во время паузы, истечение подписки до resume. Автовозврат не теряет режим и не возвращает отозванный доступ.
10. **UI-клики.** Много быстрых кликов локации/режима/питания, Back/Cancel во время запроса, клавиатура и крупный текст, открытие диагностики во время перехода. Один picker, одна операция, отсутствие зависших overlay и ложных статусов.
11. **Обновление.** Проверка при offline, malformed manifest, неверный SHA, partial/cache tampering, зависший body, отмена UAC. Повторная установка нового exact build; mandatory gate не пропадает и не блокирует пользователя бесконечной загрузкой.
12. **Подписка / оплата / админка.** Quote для первого и следующего периода, double-click, повторный webhook, конкурентные renewal/expiry/grant/revoke/refund, несколько устройств. Один согласованный реальный платёж только с отдельным разрешением; подтверждение банка делает владелец. Проверить фактический чек, восстановление и отмену автопродления только если capability действительно включён.
13. **Support / безопасность / эксплуатация.** Повреждённый/oversized отчёт, нет секрета в storage, роли admin, logout/revoke token, отказ узла, восстановление БД/резерва, достаточный disk reserve, точное соответствие всех downloads/manifests/required/minSupportedVersion.

Исторические скриншоты и старые успешные прогоны помогают выбирать сценарии, но не заменяют эту матрицу для нового candidate. Нельзя обещать отсутствие всех возможных ошибок; можно предъявить проверенные инварианты, покрытые отрицательные сценарии и честный список остаточных рисков.
