# Протокол общения и работы

Этот файл - один из главных в переносе. Он описывает, как именно пользователь ожидает работы Codex.

## Общий стиль

- Общаться на русском.
- Быть конкретным: путь, команда, следующий шаг.
- Двигаться по плану, а не прыгать между случайными идеями.
- Если пользователь просит “пошагово” - давать ровно один следующий практический шаг.
- Если пользователь просит “работай, я ухожу” - реально продолжать работу автономно.
- В финале каждого этапа давать краткий отчет.

## Автономная работа на 5-7 часов

Когда пользователь пишет, что уходит на 5-7 часов, Codex должен:

1. Выполнить `git status --short`.
2. Прочитать актуальные handoff/release docs.
3. Взять ближайший незакрытый пункт плана.
4. Реализовать его.
5. Проверить локально.
6. Если backend изменился - деплоить только backend.
7. Проверить live readiness.
8. Обновить docs.
9. Перейти к следующему пункту.

Не нужно останавливаться после первого маленького изменения, если нет настоящего блокера.

Если пункт требует владельца, например данные ЮKassa или DNS, зафиксировать blocker и взять следующий независимый пункт: monitoring, admin tooling, docs, readiness, сайт, auth cleanup.

## Интерактивная внешняя настройка

Когда пользователь рядом и настраивает внешний сервис:

- давать короткую инструкцию для текущего экрана;
- не просить сразу все данные;
- не принимать секреты в чат;
- направлять секреты в `configure_backend_env_wsl.ps1`;
- после каждого действия проверять результат;
- если сервис зависает на проверке провайдера, записать статус в docs и двигаться дальше.

Пример для ЮKassa:

- спросить `shopId`, если он не секретен;
- `secretKey` вводить только в терминале через safe env script;
- webhook URL: `https://api.greenvpn.pro/api/v1/billing/yookassa/webhook`;
- return URL: `https://api.greenvpn.pro/payment/return`;
- события webhook: `payment.succeeded`, `payment.canceled`.

## Installer policy

Пользователь не хочет новый installer после каждого промежуточного backend/admin изменения.

Новый `GreenVPN_Setup.exe` нужен:

- в самом конце большого handoff;
- или когда пользователь прямо просит остановиться и дать тестовую сборку;
- или когда менялся пользовательский Windows-клиент и нужен реальный install/fresh-user тест.

Перед выдачей финального installer нужно безопасно снести только Green VPN с локального компьютера, не трогая WireGuard, Amnezia, WARP и чужие VPN.

## Отчеты

Короткий отчет в чат:

- что сделано;
- что проверено;
- что изменено;
- что осталось;
- что требуется от владельца.

Большие отчеты и handoff - писать в `docs`, не перегружая чат.

## Старый чат

Старый чат - аварийный архив, а не основной источник.

Открывать старую переписку можно только если:

- handoff противоречит коду;
- нужно восстановить историю бага;
- пользователь прямо попросил;
- без этого нельзя принять безопасное решение.
