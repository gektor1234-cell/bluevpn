# Green VPN: что владельцу сделать для настоящей rewarded-рекламы

Этот чеклист описывает только ручные действия в кабинетах. Android production
уже работает через Yandex Mobile Ads rewarded. Windows-код и закрытый beta
web-gate готовы, но настоящий desktop Rewarded зависит от решения Яндекса.

## Текущий статус на 2026-07-19

- площадка `api.greenvpn.pro` создана в РСЯ, id площадки `19615469`;
- площадка находится на модерации;
- в поддержку отправлен запрос на подключение desktop Web Rewarded и выдачу
  рекламного block id;
- paid-beta использует отдельный безопасный `test_web`, production его не
  принимает;
- production Windows нельзя включать до получения настоящего block id формата
  `R-A-N-N` и проверки реального `onRewarded(true)`;
- юридический и платёжный профиль владелец заполняет сам: банковские,
  паспортные, налоговые данные и принятие условий агент не выполняет.

## Шаги в Яндексе

1. Открой сайт `https://ads.yandex.com/`.
2. Войди в Яндекс ID, который будет владельцем рекламного дохода.
3. Открой партнёрскую часть Рекламной сети Яндекса.
4. Выбери формат работы и выплат: самозанятый, ИП или юрлицо.
5. Заполни реквизиты для выплат.
6. Android-приложение уже подключено. Для Windows дождись решения по площадке
   `api.greenvpn.pro` и доступности desktop Rewarded.
7. В описании не используй формулировки про обход блокировок. Безопасный тон: защищённое подключение, приватность, шифрованный VPN-туннель, безопасный доступ в публичных сетях.
8. Дождись модерации приложения или доступности создания рекламного блока.
9. После одобрения создай desktop/web блок формата Rewarded.
10. Скопируй только block id формата `R-A-N-N`.
11. Передай мне только block id. Пароли, API-ключи, платёжные реквизиты и
    доступ к кабинету не нужны.

## Что я делаю после desktop block id

1. Добавляю block id только в server-only paid-beta env.
2. Отключаю beta `test_web` и включаю настоящий
   `yandex_web_rewarded` только в paid-beta.
3. Проверяю, что backend выдаёт grant только после `onRewarded(true)`, а
   закрытие/ошибка рекламы доступ не дают.
4. Проверяю один grant, одно подключение, повторный запрос рекламы после
   отключения и отсутствие принудительного таймера.
5. Только после чистого smoke продвигаю более высокую Windows-версию в
   production и сохраняю атомарный rollback.

## Важно

- Не просить пользователей кликать по рекламе.
- Не обещать доступ к заблокированным ресурсам.
- Не делать рекламу единственным смыслом приложения: Green VPN должен выглядеть и работать как полноценный VPN-сервис.
- Windows-реклама будет отдельной web-gate историей: РСЯ web-блок или прямая реклама, не мобильный rewarded SDK.
