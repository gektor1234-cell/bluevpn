# ЮKassa: подключение рекуррентных платежей — 2026-07-11

## Текущий статус

ЮKassa одобрила сохранение банковской карты для рекуррентных платежей боевого
магазина. Техническая реализация готова, но один реальный первый платеж с
сохранением способа оплаты и последующая отвязка ещё не выполнены: это ручная
проверка владельца, которую автоматизация не проводит.

## Что подготовлено

- Первый платеж сохраняет способ оплаты только при явном включении автопродления.
- Сохраненный идентификатор принимается только из authoritative-ответа ЮKassa с `payment_method.saved=true`.
- Пользователь самостоятельно отключает автопродление в Android/Windows-приложении.
- `POST /api/v1/subscription/auto-renew/cancel` устанавливает `auto_renew=0` и удаляет привязку сохраненного способа оплаты.
- Оплаченный срок сохраняется, будущие автоматические списания не создаются.
- Timeweb остается единственным billing writer; RUVDS обслуживает auth/config/VPN fallback без создания платежей.

## Обязательная проверка после разрешения

1. Создать один реальный платеж 249 RUB с включенным автопродлением.
2. Подтвердить `payment_method.saved=true` в authoritative API-ответе.
3. Проверить наличие сохраненного способа оплаты без вывода его идентификатора в UI или логи.
4. Отключить автопродление в приложении и подтвердить `auto_renew=0` и отсутствие привязки в обеих синхронизированных базах.
5. Убедиться, что повторный запуск renewal executor не создает списание после отключения.
6. Только после этого разрешить production publish и обязательное обновление.

## Ограничения до завершения реального smoke

- Не заменять smoke обычным платежом без сохранения способа оплаты: он не проверяет рекурренты.
- Не включать production auto-renew executor.
- Не публиковать новый платный stable как обязательное обновление.
- Не записывать ключ ЮKassa, payment method ID, OTP или персональные данные в репозиторий и отчеты.
